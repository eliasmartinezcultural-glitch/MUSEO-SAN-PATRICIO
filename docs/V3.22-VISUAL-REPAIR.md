# Museo Digital de San Patricio del Chañar — Reparación visual 3.22

**Estado:** candidato a publicación  
**Base documental:** 3.21.0  
**Objetivo:** reparar la experiencia pública sin rehacer el motor documental.

## Problema detectado

La arquitectura de datos ya sostiene piezas, fuentes, relaciones, colecciones, investigación y capas territoriales. La interfaz, en cambio, presentaba demasiadas estaciones consecutivas que expresaban conceptos similares:

- Descubrir
- Capas del territorio
- Consola documental
- Catálogo
- Colecciones
- Archivo

La profundidad era correcta, pero la jerarquía pública era demasiado larga.

## Decisión 3.22

La portada se reorganiza como una central de acceso:

1. Una pieza
2. Lo local
3. El tiempo
4. Investigar
5. Colecciones
6. Archivo

La profundidad permanece dentro de las fichas, relaciones, fuentes y vistas del catálogo.

## Regla visual

**Primera pantalla comprimida → central clara → profundidad bajo demanda.**

El sistema conserva:

- rutas hash;
- catálogo;
- filtros;
- búsqueda;
- fuentes internas;
- relaciones;
- colecciones;
- investigación;
- capas territoriales;
- PWA;
- accesibilidad y reduced-motion.

## Imagen

No se incorporan fotografías externas como decoración. El diseño queda preparado para un archivo fotográfico local con procedencia, autoría, fecha y derechos documentados.

La identidad territorial usa agua, río, chacras, alamedas, bardas, riego y arquitectura como gramática visual, coherente con la documentación ya registrada.

## No regresión

3.22 no convierte el museo en:

- portal turístico;
- blog;
- agenda;
- diario;
- galería decorativa;
- catálogo comercial.

La reparación es visual y de experiencia. El fondo documental continúa siendo el centro.
